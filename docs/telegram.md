# Telegram

## Авторизация

`src/lib/server/telegram/initData.ts`

Проверка подписи по официальной схеме:

1. Из строки убирается `hash`.
2. Остальные поля сортируются по имени и склеиваются через `\n`.
3. `secret = HMAC_SHA256(key="WebAppData", data=<токен бота>)`.
4. `computed = HMAC_SHA256(key=secret, data=<строка из п.2>)`.
5. Сравнение с `hash` через `timingSafeEqual`.
6. Проверка давности `auth_date`.

**Идентификатору пользователя можно доверять только после этой проверки.**
Присланный отдельно `telegram_user_id` ничего не значит — подделать его может кто
угодно. В `sync/push` идентификатор из тела запроса игнорируется и заменяется
значением из подписи; на это есть отдельный тест.

Сравнение хешей **не обычное `===`**: оно выходит на первом различающемся байте,
и по времени ответа хеш подбирается побайтово.

Срок годности подписи — 24 часа. Без него перехваченная строка оставалась бы
валидным пропуском навсегда. Дата из будущего дальше 5 минут тоже отвергается.

## Схема сессий

У Mini App серверных сессий **нет**. Строка запуска приходит с каждым запросом
в заголовке `X-Telegram-Init-Data` и проверяется на месте. Для Mini App это проще
и безопаснее куки: отсутствие состояния на сервере снимает вопросы протухания
и инвалидации.

Сессии есть только у приложения на телефоне без Telegram — см.
[ниже](#приложение-на-телефоне-без-telegram). Если в запросе есть заголовок
initData, решает только он: неверная подпись — отказ, даже при живой куке.

## Бот в чате

`src/routes/api/telegram/webhook/+server.ts` — обработчик обновлений,
`src/lib/server/telegram/botMessages.ts` — тексты и клавиатуры.

Что умеет:

- `/start`, `/app` — приветствие, три примера-кнопки и «🚀 Открыть Flux Planner»
- `/help` — короткая справка
- **фото** — разбирает блюдо на продукты и спрашивает подтверждение
- **`450 борщ`** — записывает калории с названием сразу

### Первая запись без приложения

Из новичков недели больше трети нажимали «Начать» и приложение не открывали
вовсе. Поэтому приветствие предлагает записать что-то прямо в чате: под ним
кнопки «450 борщ», «кофе 300 ₽», «зарядка в 8:00» и подсказка прислать фото.

Нажатие на пример — это ровно то же, что набрать его текст: `callback_data`
вида `try:<номер>` превращается в строку из `TRY_EXAMPLES` и уходит в
`handleFreeText`, тот же разбор и ту же запись с кнопкой отмены. В
`callback_data` лежит номер, а не текст: поле ограничено 64 байтами,
и через кнопку нельзя записать ничего, кроме наших примеров.

После самой первой записи из чата — текстом, примером, фото или весом —
к ответу добавляется строка «Это ваша первая запись…» и кнопка
«📅 Открыть мой день» (`web_app` на корень приложения: главный экран и есть
сегодняшний день). К следующим записям она не добавляется.

`/start` теперь заводит пользователя в базе: без этого бот не знал бы
о тех, кто приложение так и не открыл, и напоминать было бы некому.
Метка `/start ref_<код>` записывает приглашение по тем же правилам, что
и вход в Mini App по ссылке — только для только что заведённого
пользователя. Прочие метки (`/start tiktok`) ни на что не влияют.

Кнопка открытия Mini App строится из `TELEGRAM_MINI_APP_URL`. Telegram принимает
в `web_app` **только HTTPS** и отвергает запрос целиком, если адрес не такой,
поэтому адрес проверяется заранее: сообщение без кнопки лучше, чем ошибка Bot API
вместо приветствия. Если переменная не задана, бот прямо говорит, чего не хватает.

### Подтверждение разбора

Фото проходит через тот же `runFoodScan`, что и сканер в приложении, но результат
**не пишется в дневник сам**. Разбор кладётся в таблицу `pending_scans`
и показывается сообщением с кнопками «✅ Записать» / «✖️ Отмена».

Почему таблица, а не память процесса: `callback_data` у Telegram ограничен
64 байтами, разбор туда не помещается, а состояние в памяти не переживает
перезапуск. Запись выдаётся по паре «идентификатор + пользователь» и сразу
удаляется — чужой разбор база не отдаст, а повторное нажатие кнопки не задвоит
блюдо. Протухшие записи (старше получаса) вычищаются попутно.

Текстовая запись вида `450 борщ` подтверждения не требует: числа назвал человек,
а не модель.

### Запуск

**Локально — long polling.** Публичный адрес для самого бота не нужен:

```bash
npm run dev     # приложение
npm run bot     # в соседнем терминале
```

`scripts/bot.ts` — это транспорт, а не логика: он забирает обновления методом
`getUpdates` и переотправляет их в `/api/telegram/webhook` с тем же секретом,
который присылает Telegram. Обработчик один и тот же, отличается только способ
доставки, поэтому поведение бота локально и на сервере совпадает.

**На сервере — вебхук:**

```bash
APP_URL=https://ваш-домен npm run bot:webhook
```

Эквивалент вручную:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook"   -H "content-type: application/json"   -d '{"url":"https://ваш-домен/api/telegram/webhook","secret_token":"<TELEGRAM_WEBHOOK_SECRET>","allowed_updates":["message","callback_query"]}'
```

Вебхук закрыт секретом: Telegram присылает его в заголовке
`X-Telegram-Bot-Api-Secret-Token`. Без проверки любой желающий писал бы записи
в чужие дневники.

Обработчик **всегда отвечает 200**, даже на ошибке: Telegram считает доставленным
только успешный ответ и иначе будет повторять одно обновление по кругу.

## CloudStorage

`src/lib/server/telegram/cloudStorage.ts`

Только мелкие настройки: тема, онбординг, предпочтения уведомлений, раскладка
дашборда. Пределы Telegram — 1024 ключа и 4096 байт на значение.

**История еды, привычек и трат сюда не кладётся ни при каких условиях:** она не
помещается по объёму, не переживает переустановку и не поддаётся выборкам.
Основные данные — в базе и в IndexedDB.

## Bot API

`src/lib/server/telegram/botApi.ts` — `sendMessage`, `answerCallbackQuery`,
`editMessageReplyMarkup`, `getFilePath`, `downloadFile`, `setWebhook`.

Только серверный модуль. Токен бота даёт полный контроль над ботом, и любой его
вызов из браузера означал бы, что токен уехал в бандл.

## Mini App на клиенте

`src/lib/telegram/telegram.svelte.ts`

При открытии: `ready()`, `expand()`, цвет системного хрома, отключение закрытия
свайпом, безопасные зоны и высота окна в CSS-переменные. Всё, что появилось после
Bot API 6.0, вызывается через проверку версии — в старых клиентах этих методов
физически нет.

**Тема.** У приложения две своих палитры, тёмная и светлая (токены в
`src/routes/layout.css`). Из клиента берётся только выбор между ними —
`colorScheme` и событие `themeChanged`; цвета `themeParams` не подставляются:
подменять палитру цветами клиента значило бы получать разный продукт на разных
телефонах. Шапка, фон под окном и нижняя полоса (`setHeaderColor`,
`setBackgroundColor`, `setBottomBarColor`) красятся в фон текущей темы
(`--fx-chrome`).

В настройках есть строка «Тема: как в Telegram / Светлая / Тёмная»; выбор лежит
в синхронизируемых настройках (`settings.theme`, отсутствие поля — «как в
Telegram»). Вне Telegram «авто» следует `prefers-color-scheme`. Первый кадр
красит скрипт в `src/app.html` — по кешу выбора в localStorage (`fx-theme`),
иначе по теме клиента или системы, — поэтому вспышки чужой темы нет. Логика —
`src/lib/theme`.

**MainButton** используется точечно — там, где у экрана ровно одно завершающее
действие: «Распознать» на предпросмотре фото и «Добавить в дневник» на результате
разбора. На каждом экране она закрывала бы нижнюю часть окна и перестала бы
что-либо значить. Прежний обработчик всегда снимается через `offClick`, иначе
кнопка копит подписки и одно нажатие срабатывает несколько раз.

**Хаптика** — на подтверждениях, ошибках и подгонке порции
(`src/lib/telegram` → `haptics`). Вызовы намеренно «тихие»: отсутствие отдачи
на десктопе или в старом клиенте не должно ломать сценарий.

Вне Telegram (`isEmbedded === false`) без входа приложение открывает экран
`/login`. Кнопка «Пользоваться без входа» оставляет прежний режим: всё
локально, синхронизация и сканер выключены.

## Приложение на телефоне без Telegram

Flux ставится на главный экран iPhone и Android как обычное приложение: своя
иконка, без адресной строки, работает без сети. Данные те же, что в Mini App, —
вход привязан к аккаунту Telegram через бота.

### Вход по ссылке из бота

```
бот: /phone, кнопка «📱 Приложение на телефон», /start login
   → login_tokens: код на 10 минут, одноразовый, в базе SHA-256
   → кнопка-ссылка <домен>/login?token=… и тот же код текстом
браузер: /login → «Войти на этом устройстве» → POST /api/auth/login
   → device_sessions + кука fx_session (httpOnly, Secure, SameSite=Lax)
   → «Добавьте на главный экран»
```

- **Код** — 10 символов Crockford base32 (≈50 бит), показывается как
  `ABCDE-FGHJK`. Короткий, потому что на айфоне его иногда вводят руками:
  приложение на главном экране может не видеть куку Safari. Регистр, дефисы
  и путаница O/0, I/L/1 прощаются. Новый код гасит прежний неиспользованный.
- **Погашение** — один условный `UPDATE … WHERE used_at IS NULL AND
expires_at > now`: из двух одновременных обменов сработает один.
- **Обмен только POST'ом со страницы**, а не при открытии ссылки: превью ссылок
  и предзагрузка браузера открывают её без человека. Ссылка в сообщении бота —
  только в url-кнопке, не в тексте.
- **Пределы:** 5 кодов за 10 минут на человека (бот и приложение вместе),
  10 попыток обмена за 10 минут на адрес.
- Ссылку из Telegram на iOS стоит открыть в Safari: встроенный браузер
  Telegram не делится кукой и не умеет «На экран „Домой“». Страница говорит
  об этом прямо.

Тот же код выдаёт приложение: **Настройки → Устройства → «Получить ссылку для
входа»** (`POST /api/auth/login-link`). Внутри Mini App ссылка открывается через
`openLink` — во внешнем браузере.

### Сессия устройства

`src/lib/server/auth/deviceSessions.ts`. Кука — `id.секрет`, в базе хеш секрета.

- Срок скользящий: 90 дней от последней ротации.
- Ротация раз в неделю при запуске (`POST /api/auth/session`); прежний секрет
  принимается ещё 5 минут, чтобы параллельные запросы со старой кукой
  не выкинули человека.
- Изменяющие запросы с кукой и чужим `Origin` отклоняются (403) — поверх
  SameSite=Lax.
- Отзыв: **Настройки → Устройства** — по одному, «Выйти на этом устройстве»,
  «Выйти везде» (`/api/auth/devices`, `/api/auth/logout`). Mini App это не
  касается: она входит подписью клиента.
- Выход стирает локальные данные устройства; вход в другой аккаунт на том же
  устройстве — тоже, до первой синхронизации. Записи, сделанные без входа,
  уезжают в аккаунт.

Все эндпоинты с данными человека идут через один `requireUser`: он принимает
и подпись Telegram, и куку устройства. Ключ «Записи без Telegram»
(`/api/capture`) — отдельный механизм и работает как прежде.

### Установка и офлайн

- `static/manifest.webmanifest`: `Flux Planner` / `Flux`, `standalone`,
  `start_url: /?source=pwa`, цвета тёмной темы. Иконки 192/512, maskable
  и `apple-touch-icon.png` (180) рисует `node scripts/pwa-icons.ts` из
  `static/app-icon.png`.
- iOS: `apple-mobile-web-app-capable`, `black-translucent`, заголовок «Flux».
  Строка состояния тогда поверх приложения, отступ — `env(safe-area-inset-*)`,
  подставленный в `--fx-safe-*`, когда клиентских `--tg-*` нет. Текст строки
  состояния при `black-translucent` всегда белый — в светлой теме он читается
  хуже; это ограничение iOS.
- Android и десктопный Chrome: событие `beforeinstallprompt` откладывается
  в `app.html` и превращается в кнопку «Установить приложение»; без него —
  путь через меню браузера.
- Сервис-воркер (`src/service-worker.ts`) регистрирует `$lib/pwa` вручную и
  только вне Telegram; внутри Telegram прежние регистрации снимаются. Оболочка,
  сборка и static — из версионного кеша, страницы — сначала сеть (3 с), потом
  кеш, SDK Telegram — из кеша с фоновым обновлением. `/api/*` не кешируется
  никогда: там личные ответы.

Проверка — `tests/e2e/pwa.spec.ts` (манифест, воркер, вход по ссылке и по коду)
и `tests/integration/phone-login.test.ts` (бот → код → кука → выход). Снимки
экрана входа и установки в обеих темах — `docs/screenshots/pwa/`
(`SCREENSHOTS=1 npx playwright test tests/e2e/pwa.spec.ts`).
