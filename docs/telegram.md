# Telegram

## Авторизация

`src/lib/server/telegram/initData.ts`

Проверка подписи по официальной схеме:

1. Из строки убирается `hash`.
2. Остальные поля сортируются по имени и склеиваются через `\n`.
3. `secret = HMAC_SHA256(key="WebAppData", data=<токен бота>)`.
4. `computed = HMAC_SHA256(key=secret, data=<строка из п.2>)`.
5. Сравнение с `hash` через `timingSafeEqual`.
6. Проверка давности `auth_date`.

**Идентификатору пользователя можно доверять только после этой проверки.**
Присланный отдельно `telegram_user_id` ничего не значит — подделать его может кто
угодно. В `sync/push` идентификатор из тела запроса игнорируется и заменяется
значением из подписи; на это есть отдельный тест.

Сравнение хешей **не обычное `===`**: оно выходит на первом различающемся байте,
и по времени ответа хеш подбирается побайтово.

Срок годности подписи — 24 часа. Без него перехваченная строка оставалась бы
валидным пропуском навсегда. Дата из будущего дальше 5 минут тоже отвергается.

## Схема сессий

Серверных сессий **нет**. Строка запуска приходит с каждым запросом в заголовке
`X-Telegram-Init-Data` и проверяется на месте. Для Mini App это проще и безопаснее
куки: отсутствие состояния на сервере снимает вопросы протухания и инвалидации.

## Бот в чате

`src/routes/api/telegram/webhook/+server.ts` — обработчик обновлений,
`src/lib/server/telegram/botMessages.ts` — тексты и клавиатуры.

Что умеет:

- `/start`, `/app` — приветствие и инлайн-кнопка «🚀 Открыть Flux Planner»
- `/help` — короткая справка
- **фото** — разбирает блюдо на продукты и спрашивает подтверждение
- **`450 борщ`** — записывает калории с названием сразу

Кнопка открытия Mini App строится из `TELEGRAM_MINI_APP_URL`. Telegram принимает
в `web_app` **только HTTPS** и отвергает запрос целиком, если адрес не такой,
поэтому адрес проверяется заранее: сообщение без кнопки лучше, чем ошибка Bot API
вместо приветствия. Если переменная не задана, бот прямо говорит, чего не хватает.

### Подтверждение разбора

Фото проходит через тот же `runFoodScan`, что и сканер в приложении, но результат
**не пишется в дневник сам**. Разбор кладётся в таблицу `pending_scans`
и показывается сообщением с кнопками «✅ Записать» / «✖️ Отмена».

Почему таблица, а не память процесса: `callback_data` у Telegram ограничен
64 байтами, разбор туда не помещается, а состояние в памяти не переживает
перезапуск. Запись выдаётся по паре «идентификатор + пользователь» и сразу
удаляется — чужой разбор база не отдаст, а повторное нажатие кнопки не задвоит
блюдо. Протухшие записи (старше получаса) вычищаются попутно.

Текстовая запись вида `450 борщ` подтверждения не требует: числа назвал человек,
а не модель.

### Запуск

**Локально — long polling.** Публичный адрес для самого бота не нужен:

```bash
npm run dev     # приложение
npm run bot     # в соседнем терминале
```

`scripts/bot.ts` — это транспорт, а не логика: он забирает обновления методом
`getUpdates` и переотправляет их в `/api/telegram/webhook` с тем же секретом,
который присылает Telegram. Обработчик один и тот же, отличается только способ
доставки, поэтому поведение бота локально и на сервере совпадает.

**На сервере — вебхук:**

```bash
APP_URL=https://ваш-домен npm run bot:webhook
```

Эквивалент вручную:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook"   -H "content-type: application/json"   -d '{"url":"https://ваш-домен/api/telegram/webhook","secret_token":"<TELEGRAM_WEBHOOK_SECRET>","allowed_updates":["message","callback_query"]}'
```

Вебхук закрыт секретом: Telegram присылает его в заголовке
`X-Telegram-Bot-Api-Secret-Token`. Без проверки любой желающий писал бы записи
в чужие дневники.

Обработчик **всегда отвечает 200**, даже на ошибке: Telegram считает доставленным
только успешный ответ и иначе будет повторять одно обновление по кругу.

## CloudStorage

`src/lib/server/telegram/cloudStorage.ts`

Только мелкие настройки: тема, онбординг, предпочтения уведомлений, раскладка
дашборда. Пределы Telegram — 1024 ключа и 4096 байт на значение.

**История еды, привычек и трат сюда не кладётся ни при каких условиях:** она не
помещается по объёму, не переживает переустановку и не поддаётся выборкам.
Основные данные — в базе и в IndexedDB.

## Bot API

`src/lib/server/telegram/botApi.ts` — `sendMessage`, `answerCallbackQuery`,
`editMessageReplyMarkup`, `getFilePath`, `downloadFile`, `setWebhook`.

Только серверный модуль. Токен бота даёт полный контроль над ботом, и любой его
вызов из браузера означал бы, что токен уехал в бандл.

## Mini App на клиенте

`src/lib/telegram/telegram.svelte.ts`

При открытии: `ready()`, `expand()`, цвет системного хрома, отключение закрытия
свайпом, безопасные зоны и высота окна в CSS-переменные. Всё, что появилось после
Bot API 6.0, вызывается через проверку версии — в старых клиентах этих методов
физически нет.

Тема клиента читается (`colorScheme`, `themeParams`), но палитра остаётся своей:
тёмное стекло — часть узнаваемого вида приложения, и подменять его цветами
клиента значило бы получать разный продукт на разных телефонах. Из темы берётся
только стык с хромом Telegram.

**MainButton** используется точечно — там, где у экрана ровно одно завершающее
действие: «Распознать» на предпросмотре фото и «Добавить в дневник» на результате
разбора. На каждом экране она закрывала бы нижнюю часть окна и перестала бы
что-либо значить. Прежний обработчик всегда снимается через `offClick`, иначе
кнопка копит подписки и одно нажатие срабатывает несколько раз.

**Хаптика** — на подтверждениях, ошибках и подгонке порции
(`src/lib/telegram` → `haptics`). Вызовы намеренно «тихие»: отсутствие отдачи
на десктопе или в старом клиенте не должно ломать сценарий.

Вне Telegram приложение работает целиком локально: `isEmbedded === false`,
синхронизация и сканер выключены, интерфейс об этом говорит прямо.
