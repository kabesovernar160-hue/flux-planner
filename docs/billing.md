# Подписка и лимиты

## Что продаётся

Бесплатный тариф — **рабочее приложение, а не демонстрация**: дневник питания,
привычки, финансы, поиск по справочнику продуктов, ручной ввод, синхронизация
и выгрузка данных доступны полностью.

Платится то, что стоит денег нам — распознавание еды по фотографии, — и глубина
истории.

|                                   | Бесплатно | Pro             |
| --------------------------------- | --------- | --------------- |
| Распознавания по фото             | 3 в день  | 50 в день       |
| История и аналитика               | 30 дней   | без ограничения |
| Дневник, привычки, финансы        | да        | да              |
| Поиск по справочнику, ручной ввод | да        | да              |
| Выгрузка данных                   | да        | да              |

Цена и лимиты описаны в `src/lib/billing/plans.ts` — одном модуле для сервера
и клиента. Две копии правил разъехались бы на первом изменении цены,
и человек видел бы одно, а получал другое.

### Глубина истории

Граница считается в `utils/history.ts`, глубину текущего тарифа отдаёт
`billing.historyDays`. Аналитика закрывает замком периоды глубже границы,
календарь — дни до неё; и там, и там нажатие объясняет причину и ведёт
к тарифу.

Это ограничение показа, а не хранения: записи остаются на устройстве, в базе
и в выгрузке. Проверка живёт на клиенте — данные и так лежат у человека,
и серверная проверка ничего бы не добавила, кроме вида строгости.

`billing.historyDays` отвечает «ограничения нет», когда тариф неизвестен:
вне Telegram, при недоступном сервере, до первого ответа. Ошибаться здесь
можно только в одну сторону — показать человеку его же записи.

У Pro **честный потолок, а не «безлимит»**: каждый вызов распознавания стоит
денег провайдеру, и обещать безграничное — значит обещать то, чего не будет.

## Оплата: звёзды Telegram

Платёж проходит внутри Telegram, без карты и внешнего платёжного провайдера.

```
приложение → POST /api/billing/invoice
           → сервер: createInvoiceLink (currency XTR, subscription_period 30 дней)
           → Telegram.WebApp.openInvoice(ссылка)
           → Telegram: окно оплаты
           → вебхук: pre_checkout_query → answerPreCheckoutQuery(ok)
           → вебхук: successful_payment → начисление периода
```

**Счёт выписывает только сервер.** Цена, период и назначение платежа не зависят
от того, что прислал клиент: он сообщает лишь, какой тариф хочет.

**Пользователь берётся из обновления Telegram, а не из payload.** Payload пришёл
от нас, но подпись под ним никто не ставил — как удостоверение он не годится,
из него читается только тариф.

**Начисление идемпотентно по `telegram_payment_charge_id`.** Telegram может
доставить одно обновление дважды, и второй раз продлевать подписку нельзя.

**Возврат снимает доступ сразу.** Telegram присылает `refunded_payment`, когда
звёзды вернулись пользователю; держать после этого оплаченные возможности —
прямой убыток.

**Отмена автопродления — словом «отмена» в чате.** Бот обещает эту
возможность в сообщении об оплате, поэтому она обрабатывается правилом,
а не моделью: `editUserStarSubscription(is_canceled: true)`. Доступ при этом
не отбирается — человек заплатил за месяц, месяц у него есть, даже если
он передумал на второй день. Статус подписки не меняется: Telegram просто
перестаёт списывать, и срок истекает сам.

Возврат вручную (из поддержки): `refundStarPayment(userId, chargeId)`
в `src/lib/server/telegram/botApi.ts`. Идентификатор платежа лежит в таблице
`payments`, оттуда записи не удаляются даже при отмене — финансовая история
должна оставаться полной.

## Лимиты

`src/lib/server/quota.ts` — суточная квота на распознавание.

Она отличается от ограничителя частоты по смыслу, хотя лежит в той же таблице:
rate limit защищает сервис от потока запросов, квота — это то, что человек
купил. Поэтому окно квоты привязано к **суткам пользователя** и обнуляется
в его полночь: «3 распознавания в день» должно означать календарный день там,
где человек живёт.

Проверка стоит до чтения файла: незачем принимать пять мегабайт, чтобы потом
отказать. Исчерпанная квота отвечает `402 QUOTA_EXCEEDED` вместе с остатком —
интерфейс показывает не «ошибку», а состояние тарифа и кнопку к подписке.

Остаток возвращается и при успешном распознавании, поэтому сканер показывает
его без отдельного запроса.

## Что где лежит

| Файл                                                  | Ответственность                      |
| ----------------------------------------------------- | ------------------------------------ |
| `src/lib/billing/plans.ts`                            | Тарифы, лимиты, срок, расчёт доступа |
| `src/lib/server/billing/subscriptions.ts`             | Начисление, возврат, журнал платежей |
| `src/lib/server/quota.ts`                             | Суточные квоты                       |
| `src/routes/api/billing/invoice/+server.ts`           | Выписка счёта                        |
| `src/routes/api/billing/status/+server.ts`            | Тариф и остаток для интерфейса       |
| `src/routes/api/telegram/webhook/+server.ts`          | pre_checkout, оплата, возврат        |
| `src/lib/state/billing.svelte.ts`                     | Состояние тарифа на клиенте          |
| `src/lib/components/billing/subscription-card.svelte` | Экран подписки                       |

Доступ определяется **только записью в базе**. Приложение может сколько угодно
считать себя «про» — сервер смотрит в таблицу `subscriptions` и проверяет срок
по времени, а не по статусу: строка «active» месячной давности ничего не значит.

## Отмена

Подписка звёздами отменяется на стороне Telegram: «Настройки → Звёзды
и подписки». Приложение узнаёт об этом, когда период заканчивается и доступ
сам возвращается к бесплатному тарифу — специальной кнопки «отменить» внутри
приложения нет намеренно, чтобы не делать вид, будто мы управляем списанием.
