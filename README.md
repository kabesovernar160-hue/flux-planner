# Flux Planner

Telegram Mini App: питание, привычки и финансы одного дня на одном экране.
SvelteKit + Svelte 5 (руны), local-first, тёмный стеклянный интерфейс.

- Приложение открывается и работает **без сети**: данные лежат в IndexedDB,
  сервер догоняет в фоне.
- Распознавание еды по фото раскладывает блюдо **на компоненты** и никогда
  не пишет в дневник само — только после подтверждения человеком.
- Все секреты — токен бота, ключ ИИ — живут **исключительно на сервере**.

Подробности по слоям: [docs/architecture.md](docs/architecture.md),
[docs/backend.md](docs/backend.md), [docs/telegram.md](docs/telegram.md),
[docs/quick-capture.md](docs/quick-capture.md),
[docs/food-scanner.md](docs/food-scanner.md), [docs/sync.md](docs/sync.md),
[docs/deployment.md](docs/deployment.md).

## Экраны

| Маршрут      | Что там                                                                           |
| ------------ | --------------------------------------------------------------------------------- |
| `/`          | День целиком: калории и макросы, съеденное по приёмам пищи, привычки, траты       |
| `/analytics` | Неделя или месяц: калории и их источники, вес с целью, привычки, траты, сравнение |
| `/calendar`  | Месяц с отметками активности; выбор дня открывает его еду, вес, привычки и траты  |
| `/settings`  | Цели, вес, валюта, состояние синхронизации, выгрузка и сброс локальных данных     |
| `/habits`    | Список привычек: создание, правка, расписание, архив, удаление                    |
| `/privacy`   | Что хранится и что с этим происходит                                              |
| `/terms`     | Тарифы, оплата, возврат, границы ответственности                                  |

Записи создаются плавающей кнопкой снизу: еда (фото, поиск по справочнику или
вручную), трата или доход, привычка, вес. Любой день прошлого правится так же,
как сегодняшний — отдельного режима «только чтение» нет.

## Что внутри

- **Цели под себя.** При первом запуске — короткая анкета (пол, возраст, рост, вес,
  активность, цель). Калории считаются по формуле Миффлина–Сан Жеора, белок и жир —
  от веса тела, углеводы — остаток. Пересчитать можно в настройках: вес меняется,
  цели меняются с ним.
- **Три способа записать еду.** Фото с разбором на компоненты, поиск по встроенному
  справочнику (≈190 продуктов, работает офлайн: выбрал продукт, указал граммы —
  калории и макросы подставились) и ручной ввод.
- **Приёмы пищи.** Завтрак, обед, ужин и перекус со своим итогом у каждого —
  видно не только сколько, но и где перебрал. Приём подставляется по времени
  суток и правится одним нажатием.
- **Повтор в одно нажатие.** Человек ест одно и то же: над поиском стоит ряд
  из того, что он уже записывал в этот приём. Поиск заглядывает и в свои записи —
  «борща маминого» в справочнике нет, а в истории он есть.
- **Дневник веса.** Запись шагами по сто граммов, график с шкалой по размаху
  значений, необязательная цель и честный прогноз: дата называется, только
  когда для неё есть основания.
- **Деньги с двух сторон.** Расходы с категориями и лимитом дня, доходы со своими
  категориями, баланс дня и периода.
- **Привычки с расписанием.** Каждый день, по будням или свои дни недели; серии
  считаются только по запланированным дням.
- **Выгрузка данных.** JSON — полный снимок, CSV — таблица о еде. Без сервера
  и без просьб «напишите в поддержку».
- **Запись без Telegram.** Личный ключ в «Быстрой команде» на айфоне:
  кнопка «Действие», двойное касание крышки или Siri — сказали «ужин в 19:00»,
  и запись в дневнике, не открывая ни чат, ни приложение.
  Подробности: [docs/quick-capture.md](docs/quick-capture.md).
- **Уведомления.** Итоги дня в чате с ботом — по местному времени человека,
  а не по времени сервера, — и дневное напоминание о незакрытых привычках.
  С переключателем в настройках.

## Быстрый старт

```bash
npm install
cp .env.example .env
npm run dev
```

Приложение поднимется на `http://localhost:5173`. В обычном браузере оно
работает целиком локально: дневник, привычки, траты, ручной ввод еды.
Распознавание по фото в браузере недоступно — эндпоинт требует подписи
Telegram (см. [Проверка внутри Telegram](#проверка-внутри-telegram)).

На пустом хранилище dev-сервер заполняет дневник демо-данными. Чтобы увидеть
первый запуск глазами новичка — пустую главную, приветствие, подсказку у «+», —
откройте `http://localhost:5173/?seed=off` в чистом профиле браузера.
Выбор запоминается в localStorage, `?seed=on` возвращает сид обратно.

## Переменные окружения

Все читаются только на сервере через `$env/dynamic/private` и в бандл клиента
не попадают.

| Переменная                | Обязательна       | Что ломается без неё                                                               |
| ------------------------- | ----------------- | ---------------------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`      | да                | Нечем проверить подпись → авторизация, синхронизация и сканер отвечают 500         |
| `TELEGRAM_MINI_APP_URL`   | для бота          | Бот не покажет кнопку открытия приложения                                          |
| `TELEGRAM_BOT_USERNAME`   | нет               | Ссылки-приглашения ведут на `fluxplanner_xbot` — задать для тестового бота         |
| `TELEGRAM_WEBHOOK_SECRET` | для бота          | Вебхук отвечает 401 на всё                                                         |
| `APP_URL`                 | для скриптов бота | `npm run bot` не найдёт приложение, `npm run bot:webhook` не зарегистрирует вебхук |
| `AI_API_KEY`              | для распознавания | В разработке работает детерминированный мок, в продакшене эндпоинт отвечает 500    |
| `DATABASE_URL`            | нет               | Используется файл `flux-planner.db` рядом с проектом                               |
| `CRON_SECRET`             | для рассылки      | Эндпоинт ежедневной рассылки отвечает 500                                          |

## Telegram-бот

### 1. Создать бота

1. Открыть [@BotFather](https://t.me/BotFather) и отправить `/newbot`.
2. Задать имя и адрес бота.
3. BotFather пришлёт **токен** вида `8585094426:AAH...`. Это и есть
   `TELEGRAM_BOT_TOKEN`.

Токен даёт полный контроль над ботом. Он нужен серверу для проверки подписи
`initData` и для отправки сообщений — в клиентский код он не попадает никогда.

### 2. Указать адрес Mini App

`TELEGRAM_MINI_APP_URL` — публичный адрес приложения **по HTTPS**. Telegram
отвергает кнопку с `http://`, поэтому локально нужен туннель:

```bash
npm run dev:tunnel
# в соседнем терминале:
cloudflared tunnel --url http://localhost:5173
```

Полученный адрес (`https://что-то.trycloudflare.com`) и есть
`TELEGRAM_MINI_APP_URL`. Домены `trycloudflare.com` и `ngrok` уже разрешены
в `vite.config.ts`.

Кнопка меню в чате, список команд и описания бота ставятся одной командой —
см. [шаг 3](#3-настроить-профиль-бота).

### 3. Настроить профиль бота

Команды, кнопка меню и описания по умолчанию пусты: человек открывает чат
и видит бота без единой подсказки. Всё это ставится одной командой, когда
в `.env` уже есть токен и адрес Mini App:

```bash
npm run bot:setup
```

Скрипт регистрирует команды `/start`, `/app`, `/help`, вешает кнопку меню
на адрес приложения и записывает описание бота — то, что видно в пустом чате
и в профиле. Повторный запуск просто перезаписывает значения, поэтому после
смены адреса приложения его нужно выполнить снова.

Имя и аватар остаются за BotFather: Bot API их не меняет.

### 4. Включить Main Mini App

Это то, что даёт **кнопку «Открыть» прямо в списке чатов** — приложение
запускается, не заходя в переписку. Настраивается только в BotFather, метода
в Bot API для этого нет:

```
@BotFather → /mybots → выбрать бота → Bot Settings → Configure Mini App
→ Enable Mini App → прислать адрес из TELEGRAM_MINI_APP_URL
```

После этого работают прямые ссылки:

- `t.me/имя_бота/app` — открыть приложение
- `t.me/имя_бота/app?startapp=scan` — открыть сразу на сканере еды

### 5. Запустить бота

Придумайте длинную случайную строку для `TELEGRAM_WEBHOOK_SECRET` и заполните
`.env`:

```
TELEGRAM_BOT_TOKEN=8585094426:AAH...
TELEGRAM_MINI_APP_URL=https://что-то.trycloudflare.com
TELEGRAM_WEBHOOK_SECRET=длинная-случайная-строка
APP_URL=http://localhost:5173
```

**Локально** — long polling, публичный адрес для самого бота не нужен:

```bash
npm run dev     # приложение
npm run bot     # в соседнем терминале
```

`scripts/bot.ts` не содержит логики бота: он забирает обновления у Telegram
и переотправляет их в тот же `/api/telegram/webhook`, который работает
в продакшене. Поведение на ноутбуке и на сервере одинаковое.

**На сервере** — вебхук, отдельный процесс не нужен:

```bash
APP_URL=https://ваш-домен npm run bot:webhook
```

### Что умеет бот

| Сообщение               | Что делает                                                   |
| ----------------------- | ------------------------------------------------------------ |
| `/start`, `/app`        | Приветствие и кнопка «🚀 Открыть Flux Planner»               |
| `/help`                 | Короткая справка                                             |
| «сегодня в 19:00 ужин»  | Разбирает словами и кладёт в план, рядом кнопка отмены       |
| «потратил 500 на такси» | Записывает трату                                             |
| «съел овсянку»          | Записывает в дневник питания                                 |
| фото                    | Разбирает блюдо на продукты и **спрашивает подтверждение**   |
| `450 борщ`              | Записывает калории с названием сразу — числа назвал человек  |
| `вес 78,4`              | Записывает взвешивание за сегодня                            |
| «отмена»                | Отключает автопродление подписки, оплаченный период остаётся |

Разбор словами работает и без ключа ИИ — тогда по ключевым словам, заметно
грубее. Калории по названию не выдумываются никогда: их считает справочник
или распознавание по фото.

### Быстрый запуск с телефона

Прямые ссылки открывают приложение сразу на нужном действии:

| Ссылка                               | Что откроется  |
| ------------------------------------ | -------------- |
| `t.me/имя_бота/app`                  | Приложение     |
| `t.me/имя_бота/app?startapp=scan`    | Сканер еды     |
| `t.me/имя_бота/app?startapp=expense` | Новая трата    |
| `t.me/имя_бота/app?startapp=income`  | Новый доход    |
| `t.me/имя_бота/app?startapp=habit`   | Новая привычка |

На айфоне их можно повесить на жест или кнопку:

1. **Быстрые команды** → новая команда → действие «Открыть URL» → вставить ссылку.
2. **Кнопка «Действие»**: Настройки → Кнопка «Действие» → Быстрая команда → выбрать её.
3. **Двойное касание задней крышки**: Настройки → Универсальный доступ → Касание →
   Касание задней панели → Двойное касание → выбрать ту же команду.

Получается: двойной тап по крышке — и открыт сканер еды.

## Тарифы

Бесплатный тариф — рабочее приложение: дневник, привычки, финансы, поиск
по справочнику, ручной ввод, синхронизация и выгрузка данных без ограничений.
Платится то, что стоит денег нам, — распознавание по фото:

|                       | Бесплатно | Pro (100 ⭐ в месяц) |
| --------------------- | --------- | -------------------- |
| Распознавания по фото | 3 в день  | 50 в день            |
| История и аналитика   | 30 дней   | без ограничения      |
| Всё остальное         | да        | да                   |

Оплата — звёздами Telegram, внутри приложения, без карты. Подписка на 30 дней
с автопродлением, отменяется в настройках Telegram. Подробности и устройство:
[docs/billing.md](docs/billing.md).

## Проверка внутри Telegram

1. Поднять туннель и указать его адрес в `TELEGRAM_MINI_APP_URL`.
2. Запустить `npm run dev:tunnel` и `npm run bot`.
3. В чате с ботом отправить `/start` и нажать кнопку.

Приложение получит от клиента подписанную строку `initData`, отправит её
на `/api/auth/telegram`, сервер проверит подпись — и только после этого
пользователь считается авторизованным.

## Food Scanner

Главный принцип: **модель не знает точных калорий по фотографии**. Она не видит
масло на сковороде, сахар в соусе и не умеет измерять вес. Поэтому распознавание
и расчёт ценности разделены:

```
фото → проверка и сжатие на клиенте → AI Vision → компоненты блюда и вес
     → справочник питания → калории и макросы → уверенность
     → ПОКАЗ ПОЛЬЗОВАТЕЛЮ → правка → подтверждение → дневник
```

Модель отвечает на вопрос «что видно и сколько этого примерно»: возвращает
список компонентов («Куриная грудка 150 г», «Рис 200 г», «Соус 30 г»), способ
приготовления и честную уверенность. Калорийность берётся из справочника
и умножается на вес. Продукт, которого в справочнике нет, считается по оценке
модели и помечается пониженной уверенностью.

Результат **всегда** показывается человеку: каждый компонент можно
переименовать, поправить граммы (значения пересчитываются сразу) или убрать.
Записи появляются в дневнике только после кнопки «Добавить в дневник».

### Чего ждать не стоит

- Точного веса порции. По фотографии он определяется приблизительно — это
  главный источник ошибки, и поэтому граммы вынесены в интерфейс.
- Скрытых ингредиентов: масла, сахара, сливок внутри соуса.
- Состава сложных блюд без визуальных признаков.

Если еды на фото не видно, снимок тёмный или размытый — сканер честно говорит
«не удалось определить» и предлагает переснять или ввести вручную, а не
показывает выдуманный результат.

### Подключение провайдеров

**Vision.** Сейчас это Anthropic (`AI_API_KEY`). Замена — новая реализация
`VisionFoodProvider` в `src/lib/server/ai/providers/` и одна строка
в `src/lib/server/ai/visionProvider.ts`. Интерфейс: изображение на входе,
структурированный разбор на компоненты на выходе. Промпт лежит отдельно —
`src/lib/server/ai/prompt.ts`.

**Питание.** Сейчас это локальная таблица на ~190 продуктов
(`src/lib/server/ai/providers/nutritionData.ts`). Внешняя база (USDA FoodData
Central, Open Food Facts) подключается реализацией `NutritionProvider`
в `src/lib/server/ai/nutritionProvider.ts`:

```ts
interface NutritionProvider {
	searchFood(query: string): Promise<FoodNutrition[]>;
	getNutrition(foodId: string): Promise<FoodNutrition | null>;
}
```

Ни сканер, ни интерфейс о такой замене не узнают: pipeline знает только
про этот контракт. Ключ внешнего API, если он появится, читается на сервере.

## Продакшен

На своём сервере нужен только Docker: приложение и Caddy поднимаются одной
командой, сертификат Let's Encrypt Caddy получает и продлевает сам.

```bash
cp .env.example .env   # заполнить, включая DOMAIN и ACME_EMAIL
docker compose up -d --build
```

Затем — вебхук и профиль бота прямо из контейнера:

```bash
docker compose exec app node scripts/set-webhook.ts
docker compose exec app node scripts/bot-setup.ts
```

Без Docker — `npm ci && npm run build && ORIGIN=https://домен node build`.

Есть и второй путь — Vercel с базой Turso: адаптер выбирается по окружению,
менять ничего не нужно. Он даёт постоянный https-адрес бесплатно, но Hobby
запрещает коммерческое использование, а приложение продаёт подписку —
подробности и оговорки в [docs/deployment.md](docs/deployment.md#vercel-и-turso).

Конфигурация проверяется при старте: приложение либо поднимается с рабочими
настройками, либо не поднимается и говорит, чего не хватает. База — libSQL:
локально файл, на сервере файл на постоянном томе, на хостинге удалённая;
схема накатывается миграциями автоматически. Живость — `GET /api/health`.
Резервные копии — `scripts/backup.sh`. Пошаговый выкат, расписание и
обслуживание: [docs/deployment.md](docs/deployment.md).
